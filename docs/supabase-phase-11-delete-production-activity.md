# Supabase Phase 11: Delete Production Activities

Phase 11 lets authorized Calendar users remove an entire Production activity
from the active calendar without destroying its persisted audit trail.

## Behavior

Selecting **Delete** from any EXT, Shutter, DM, HW, Install only, division or
Lock up event opens a confirmation dialog. Confirming acts on the shared
Production activity, so every event generated by that group disappears after
the repository reloads active activities.

Deletion is a soft cancellation. `production_activities.status` changes from
`ACTIVE` to `CANCELLED`, `cancelled_at` and `updated_by` are recorded, and the
related Lots, stages, schedules and date history remain stored. A cancelled
activity cannot be cancelled or edited again through the active Calendar.

## Security boundary

`ADMIN`, `PROJECT_MANAGEMENT` and `SCHEDULING` can call
`cancel_production_activity`. The exposed function is a security-invoker
wrapper; its implementation is kept in `private`, derives the actor from
`auth.uid()`, repeats the role check and pins an empty `search_path`.

Anonymous and `READ_ONLY` users are denied. Authenticated browser clients still
have no direct `DELETE` or `UPDATE` grants on Production or date-history tables.
Customer Service and Extra / Change Orders remain outside this phase.

The remote lifecycle creates a disposable three-stage Production group,
cancels it as `ADMIN`, verifies that it no longer matches the active Calendar
query while all detail rows remain, denies `READ_ONLY` and anonymous calls, and
finishes with `rollback`.
